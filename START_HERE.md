# MATCHDAY — начать здесь

Это **пакет документации**, а не готовое Android-приложение. Поместите эти файлы в корень нового проекта, созданного через Android Studio (Empty Activity, Kotlin, Jetpack Compose). Код приложения должны реализовать и проверить участники.

## Порядок, который нельзя менять

1. **Все четверо** читают `docs/01_SCOPE.md` и `docs/02_ARCHITECTURE.md`.
2. **Участник 1** создаёт Android-проект, запускает пустое приложение на эмуляторе и создаёт GitHub-репозиторий. Вносит документацию, настраивает Git. Первый коммит — реально запускаемый проект, а не пустая папка.
3. **Все** принимают приглашения Collaborator, клонируют репозиторий и на своих компьютерах проверяют `git status`, `git log`, запуск проекта. На каждом устройстве своя GitHub-учётная запись.
4. **Участник 1** в первой ветке `feat/p1-foundation` создаёт модели, in-memory repository, AppViewModel, маршруты-заглушки. Создаёт PR, участник 2 проверяет, затем изменения попадают в `main`.
5. Все читают **контракт** `docs/03_CONTRACTS.md` и **распределение** `docs/04_TEAM_TASKS.md`. Только после мержа foundation участники 2, 3, 4 создают свои ветки от свежего `main`.
6. **Участники 2, 3, 4** реализуют только собственные папки и открывают PR; при конфликте контрактов — не менять чужие файлы, а согласовать через участника 1.
7. **Участник 1** интегрирует экраны с реальными навигационными маршрутами отдельной веткой и PR после принятия остальных PR.
8. Все запускают проверки из `docs/07_QA_DEFENSE.md`, проводят репетицию защиты, убеждаются, что каждый понимает свой код и имеет ≥10 осмысленных собственных коммитов.
9. Ссылку на GitHub передать преподавателю **до защиты Week 12**.

## Индекс файлов

- `CONTRIBUTING.md` — правила работы в репозитории и границы ответственности.
- `README.md` — описание проекта для GitHub (впишите реальные имена).
- `docs/01_SCOPE.md` — точная граница функционала первой недели.
- `docs/02_ARCHITECTURE.md` — структура, модель, MVVM, данные.
- `docs/03_CONTRACTS.md` — маршруты и точные интерфейсы экранов.
- `docs/04_TEAM_TASKS.md` — 4 роли, разрешённые папки и 40 содержательных этапов.
- `docs/05_GIT_WORKFLOW.md` — работа с ветками, GitHub и PR.
- `docs/06_DESIGN_SYSTEM.md` — минимальные правила дизайна и wireframe.
- `docs/07_QA_DEFENSE.md` — тесты, демонстрация и вопросы для защиты.
- `docs/08_ROADMAP.md` — осторожный план Weeks 13–14 (не официальные требования).
- `tasks/P1_LEAD.md`, `tasks/P2_MATCHES.md`, `tasks/P3_TEAMS.md`, `tasks/P4_TOURNAMENTS_UI.md` — отдельные рабочие задания каждому.
- `prompts/ROLE_PROMPTS.md` — шаблоны задач для четырёх ролей.
- `.github/pull_request_template.md` — шаблон проверки PR.

## Источник требований

`Requirements 1 & 2: App Architecture, UI & Navigation — Android Group Project, Week 12` (2 страницы, предоставлены преподавателем). Из документа точно известно, что то же приложение продолжается Weeks 12–14. Требования Weeks 13 и 14 **не предоставлены**.

## Правило проекта

Приоритет: **работающий, понятный код > количество фич > визуальные эффекты**. Автоматическое объединение PR с `main` запрещено. Каждый участник проверяет свой код и может объяснить, как он работает.
