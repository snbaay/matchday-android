# 01 — Спецификация MATCHDAY: Week 12

> Имена строковых маршрутов ниже отражают исходный контракт. После согласованного рефакторинга используются типизированные маршруты; см. `09_CLEAN_ARCHITECTURE.md`. Шесть пользовательских сценариев и правила данных сохраняются.

## Цель

Небольшое локальное Android-приложение для организации турниров по футболу/FIFA. Это учебный проект для четырёх начинающих Android-разработчиков. Критерий готовности: демонстрационный сценарий работает на эмуляторе, код понятно объясняется преподавателю.

## Ровно шесть маршрутов

1. `tournaments` — список турниров + создание турнира в диалоге.
2. `tournament/{tournamentId}` — обзор: название, количество команд/матчей, кнопки разделов.
3. `tournament/{tournamentId}/teams` — список команд + добавление команды в диалоге.
4. `tournament/{tournamentId}/matches` — матчи + создание матча в диалоге.
5. `match/{matchId}/score` — ввод/изменение счёта отдельным экраном.
6. `tournament/{tournamentId}/standings` — турнирная таблица.

Диалоги — это части соответствующих экранов, а не отдельные маршруты.

## Четкие правила данных

- Турнир: `id`, `name`; пустые названия отклоняются, пробелы по краям удаляются, длина 1..60 символов.
- Команда: `id`, `tournamentId`, `name`; в одном турнире одинаковые названия без учёта регистра запрещены; 1..40 символов.
- Матч: `id`, `tournamentId`, `homeTeamId`, `awayTeamId`, `homeScore?`, `awayScore?`.
- Команды матча разные, обе принадлежат одному турниру. Для Week 12 одна пара команд может сыграть не больше одного матча (порядок home/away не влияет на проверку дубликата).
- Новый матч ещё не сыгран: оба счёта `null`.
- Завершённый матч: оба счёта заданы, целые числа от 0 до 99.
- Счёт разрешается заменить. Таблица пересчитывается по всем матчам заново.
- Начисление очков: победа 3; ничья 1; поражение 0.
- Сортировка таблицы: очки ↓, разница голов ↓, забитые голы ↓, название команды ↑ (для устойчивого результата).
- Незавершённый матч не влияет на таблицу. Команды без матчей показываются с нулями.
- Данные живут только в памяти процесса; после перезапуска могут исчезнуть. Это ограничение **открыто** показываем на защите.

## Полезные сценарии

- Пользователь создал турнир и видит его в списке.
- Пользователь создал 4 команды и видит количество команд в dashboard.
- Пользователь создал матч из двух команд.
- Пользователь ввёл счёт 3:1; победитель получил три очка, а проигравший ноль.
- Пользователь изменил 3:1 на 0:0, таблица пересчиталась и обе команды получили по одному очку.
- Пользователь нажал системную или экранную кнопку Back и вернулся без дублированных экранов.

## Предельный объём Week 12

**Делаем:** формы, списки, состояния empty/success/error, матчи, таблица, навигация, тесты ключевой логики, единый Material 3 дизайн.

**Не делаем:** учёт игроков, календарь матчей, плей-офф, авторизацию, комнатную синхронизацию, сервер, Firebase, Room, автоматическую генерацию матчей, QR, push-уведомления, загрузку фотографий, ставки, сложные анимации.

## Чёткий Definition of Done

- Все шесть маршрутов открываются, и Back работает.
- Хотя бы один `tournamentId` и один `matchId` передаются в navigation arguments.
- Все действия меняют реальное состояние через `AppViewModel` и repository; UI обновляется без ручного refresh.
- Проверки ошибочных вводов работают; crash при пустом списке нет.
- Gradle build успешен, unit tests ключевой логики проходят, демонстрация на эмуляторе проведена.
- У всех 4 участников ≥10 **реальных осмысленных** коммитов, GitHub-аккаунты и авторство корректны; README с именами.
- Все 4 участника понимают свои изменения.
