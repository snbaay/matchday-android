# 07 — QA, демонстрация и индивидуальная защита

## Перед каждым PR

- [ ] Изменены только разрешённые папки текущей роли.
- [ ] Проверены комментарии/незакрытые TODO, нет фиктивных значений вместо настоящих state.
- [ ] Нет `local.properties`, ключей, токенов, `build/` в Git.
- [ ] Сборка Windows: `.\gradlew.bat :app:assembleDebug` (macOS/Linux: `./gradlew :app:assembleDebug`).
- [ ] Unit tests: `.\gradlew.bat :app:testDebugUnitTest` (или аналоги на macOS/Linux).
- [ ] UI проверен на эмуляторе/устройстве. Если нет эмулятора или SDK — точно указать, что НЕ проверено.
- [ ] PR описывает, что сделано, какие ошибки были и как вручную проверить.
- [ ] Автор способен объяснить функциональность без чтения подсказок Codex.

## Ручной обязательный smoke-test Week 12

1. Установить и открыть приложение; пустой список турниров должен отображаться нормально.
2. Попробовать создать турнир с пустым именем: должна появиться ошибка.
3. Создать `SDU FIFA Cup`: карточка появляется в списке.
4. Открыть турнир: dashboard показывает 0 команд и 0 матчей.
5. Открыть Teams, добавить `Real Madrid`, `Barcelona`, `Arsenal`, `Liverpool`.
6. Попробовать добавить `real madrid` ещё раз: дубликат блокируется.
7. Открыть Matches: создать Real Madrid vs Barcelona.
8. Попробовать выбрать одну и ту же команду обеими сторонами: запрещено.
9. Открыть Score, ввести `3` и `1`, сохранить.
10. Открыть Standings: Real Madrid 3 pts, Barcelona 0 pts, GD +2/-2.
11. Вернуться в матч, заменить счёт на `0:0`; Standings: обе команды 1 pt. Матч посчитан один раз, а не два.
12. Попробовать отрицательный, нечисловой или больше 99 счёт — приложение не падает.
13. Системный Back и стрелки Back работают на всех вложенных экранах.
14. Повернуть экран (если доступно) — данные в ViewModel остаются в рамках процесса; отсутствует crash.
15. Проверить кнопки на пустых списках, длинные имена, базовую читаемость.
16. Закрыть и полностью перезапустить app: **допустимо**, что данные исчезнут, это известное ограничение Week 12. Не утверждать обратное.

## Unit tests, которые стоит сделать

- Repository: создание турнира меняет StateFlow; название trim; пустое имя -> failure.
- Repository: команда в турнире; одинаковое имя без учёта регистра -> failure.
- Repository: матч не создаётся между одной командой; не допускаются команды из другого турнира; повтор пары отклоняется.
- Repository: счёт 3:1 сохраняется, счёт -1:2 или 100:1 отклоняется.
- Calculator: победа 3/0; ничья 1/1; нулевые строки; незавершённый матч игнорируется.
- Calculator: по разнице голов и голам сортировка работает, редактирование счёта пересчитывает таблицу.

## Демонстрация преподавателю (2–4 минуты)

- P4 показывает список и создаёт турнир.
- P3 добавляет команды, демонстрирует валидацию повторного имени.
- P2 создаёт матч, вводит счёт и показывает таблицу, объясняет 3/1/0.
- P1 открывает `MainActivity`, `AppViewModel`, `InMemoryTournamentRepository`, `AppNavGraph`; показывает StateFlow и передачу `matchId`, GitHub с 4 авторами коммитов.
