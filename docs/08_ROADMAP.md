# 08 — План развития: Weeks 12–14

## Что подтверждено источником

Из PDF Week 12 следует: **одна группа выбирает одну идею и продолжает именно то же приложение на Weeks 12–14**. В файле нет официального списка требований Week 13/Week 14. Поэтому всё ниже — **гипотезы и варианты**, а не обещание соответствия будущим заданиям.

## Week 12 — Foundation (официально задано)

- Kotlin + Jetpack Compose и Material 3
- MVVM + ViewModel + StateFlow
- Несколько функциональных UI screens
- Navigation Compose + аргумент screen ID + Back
- GitHub с 4 членами и ≥10 осмысленных commits каждого
- README, работающая демонстрация и индивидуальная защита

## Week 13 — если преподаватель попросит хранение данных

**Вариант:** заменить in-memory repository на Room, сохранить UI и публичные методы ViewModel по возможности. Появится долговременное хранение турниров/команд/матчей после перезапуска. Таблицы потенциальной БД:

- `tournaments(id PRIMARY KEY, name)`
- `teams(id PRIMARY KEY, tournamentId FOREIGN KEY, name)`
- `matches(id PRIMARY KEY, tournamentId FOREIGN KEY, homeTeamId FOREIGN KEY, awayTeamId FOREIGN KEY, homeScore NULL, awayScore NULL)`

Это **не** требование Week 12. Если Week 13 окажется про другое (networking, sensors, background), спланировать минимальное расширение того же MATCHDAY после чтения нового PDF.

## Week 14 — если преподаватель попросит больше бизнес-функций/UI

**Вариант:** playoff на 4 команды, история турниров, дополнительная статистика и более аккуратное оформление. Не добавлять всё сразу; выбирать только функции, которые реально нужны по заданию.

## Главный принцип будущих недель

Не менять идею и не начинать проект заново. После каждой недели сохранять рабочую сборку в `main` и делать небольшой новый scope-документ `docs/WEEK_13_REQUIREMENTS.md` или `docs/WEEK_14_REQUIREMENTS.md`, когда преподаватель выдаст соответствующий документ.
